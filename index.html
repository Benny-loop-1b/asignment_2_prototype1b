Project Introduction

Loop Together is a browser-based audio instrument designed for simple, social and playful music creation. My extended technique is looping and sampling, and the project is intended for general users rather than experienced music producers.

For this assignment I explored two design areas. The first area focuses on how users create and understand loops. The second area focuses on how the interface gives feedback when the system is recording, playing or responding to sound.

I created three prototypes for each area so I could compare different approaches without deciding on one final design too early.

Area 1 — Looping Interaction Prototypes

My first area of exploration is looping interaction. Because looping and sampling is the extended technique in my project, I wanted to test different ways users could understand repetition and control timing.

The three prototypes move from a very simple button-based interaction to more visual and direct forms of rhythm control. The goal is not to decide which version is best yet, but to explore how different layouts change the way users understand a loop.

Prototype 1A — Button Loop

Open Prototype 1A

This was my starting version. I used familiar Record, Stop Recording, Play Loop and Stop Loop buttons because these controls are already common in media players.

I wanted this version to be very simple so a first-time user could focus on recording a sound and hearing it repeat, without needing to understand rhythm grids or sequencing.

Main question: Is a familiar button interface enough to make looping easy to understand for a beginner?

Prototype 1B — Circular Loop

Open Prototype 1B

In this version I wanted the loop to visually feel repetitive. Instead of showing timing as a straight horizontal line, I arranged eight beats around a circle.

The active beat moves around the circle while the sequence is running. The final beat sits next to the first beat, which makes the repeating structure more visible.

Main question: Does a circular layout help users understand that the rhythm continuously returns to the beginning?

Prototype 1C — Step Loop

Open Prototype 1C

The third version gives the user more direct control over rhythm. The interface contains eight steps, and the user can turn individual steps on or off to decide when the recorded sound should play.

I wanted to explore something closer to a simple sequencer while still keeping the interface understandable for users who do not have music-production experience.

Main question: Does selecting individual beats make looping feel more creative without making the interface too complicated?

Area 2 — Feedback Design Prototypes

My second area of exploration is feedback design. While developing the instrument, I noticed that users need to know whether the microphone is active, whether a sound has been recorded and whether the system is responding.

These three prototypes explore different ways of communicating that information: visual movement, text instructions and expressive animation.

Prototype 2A — Visual Feedback

Open Prototype 2A

This prototype uses a live volume meter and a pulsing visual element to show microphone activity. When the user makes a louder sound, the visual response becomes larger.

I wanted to test whether users could understand that the microphone was working without reading a long instruction.

Main question: Can movement alone clearly communicate that the system is listening and responding?

Prototype 2B — Text Feedback

Open Prototype 2B

This version uses short step-by-step text instructions. The interface tells the user when to record, when to stop and when the sound is ready to play.

I kept the instructions short because the project is designed for general users. The aim is to make the process easy to follow without adding technical audio terms.

Main question: Do simple instructions reduce confusion for first-time users?

Prototype 2C — Expressive Feedback

Open Prototype 2C

The final feedback prototype uses animated graphics that react directly to microphone input. Sound is translated into movement so the interface feels less like a utility and more like a creative instrument.

I wanted this version to explore whether feedback can also make the interaction more enjoyable, rather than only communicating a system state.

Main question: Does expressive animation make the experience feel more playful and musical?

Peer User Testing

I will use the six prototypes during peer user testing. I want to compare how users understand the different looping interactions and feedback styles before developing the final version.

My testing will focus on clarity, ease of use, understanding of repetition, feedback visibility and how enjoyable each interaction feels.
